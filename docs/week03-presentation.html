What Is a Mental Model?

メンタルモデルとは？

A mental model is the simplified, often incomplete picture a person carries in their head of how something works — built from experience, not from reading a manual.

メンタルモデルとは、人が頭の中に持っている、ある物事がどう働くかについての、簡略化された、しばしば不完全な絵です。マニュアルを読んで作られるのではなく、経験から作られます。

You don't need to know how a refrigerator's compressor works to use one well. Your mental model — "colder on the left, don't leave the door open" — is wrong in detail and right enough to be useful.

Norman's Three Models

ノーマンの3つのモデル

Design Model

The designer's accurate model of how the system actually works

System Image

What the user can actually see, hear, and touch — the only evidence they get

User's Mental Model

What the user believes, built entirely from the system image

The designer and the user never talk directly. The system image is the only channel between them — if it's misleading, the user's mental model will be wrong, no matter how correct the design model is.

Working Memory: The Real Number

ワーキングメモリ：本当の数字

The Famous Number

7 ± 2

Miller, 1956 — often quoted, but Miller himself used it loosely, and it measured best-case conditions

The Revised Number

~4

Cowan, 2001 — closer to the real limit once rehearsal tricks are controlled for

The design lever isn't the number — it's chunking. Group related items, and each group counts as one "slot," not five. A phone number is easier as 090-1234-5678 than as ten separate digits.

Recognition Beats Recall

再認は再生に勝る

Recall | 再生

Pull information out of memory with no help: remembering a command, a password, a menu path

Effortful, error-prone

Recognition | 再認

See a cue and confirm it's right: picking an icon, a visible menu item, a suggested reply

Fast, reliable

Minimize what users have to remember. Show them options instead of asking them to recall commands.

When Mental Models Go Wrong: AI Agents

AIエージェントでメンタルモデルが誤るとき

A toaster has an obvious system image: a slot, a lever, a dial. An AI agent mostly doesn't. That's a real design problem.

Over-trusting

Users assume the agent "understands" like a person, and don't check its work

Under-trusting

Users can't tell what the agent is capable of, so they avoid useful features entirely

Recall from Session 1: showing sources, confirming before consequential actions, and stating limits aren't just politeness — they rebuild the system image an agent doesn't naturally have.

Evaluating Without Users: The Cognitive Walkthrough

認知的ウォークスルー

A cognitive walkthrough is an inspection method — you evaluate a design yourself, step by step, without needing to recruit real users. It's built specifically to catch learnability problems. (Wharton, Rieman, Lewis & Polson, 1994)

At every step, ask four questions | 各ステップで4つの質問をする

1. Will the user try to achieve the right effect?
2. Will the user notice the correct action is available?
3. Will the user associate the correct action with the effect they want?
4. If they do it, will they see that progress is being made?

Any "no" becomes a failure story — a written hypothesis of exactly where and why a real user would get stuck.

Worked Example: One Task, Four Questions

ワークド・エグザンプル

Task: ask an AI assistant to summarize a long document you just uploaded.

1. Right effect? Yes — the user knows they want a summary.
2. Notice the action? Maybe — is "upload" visible, or hidden behind a small icon?
3. Associate action with effect? Risk — does the upload icon look like it leads to summarizing, or just "attach a file"?
4. See progress? Risk — if the agent takes 8 seconds, is there a visible "reading your file..." state?

Two "maybe/risk" answers are two failure stories — concrete things to test or fix, found without a single real user.

Designing to Match Mental Models

メンタルモデルに合わせてデザインする

  • Chunk information into groups of about four, not long flat lists
  • Use recognizable metaphors — a trash can, a folder, a send arrow — so the system image carries meaning instantly
  • Favor recognition over recall — show options, don't make people remember commands
  • Make the system image honest — if an AI agent can't undo an action, don't show an icon that implies it can

Bringing This to AI and Agent Interfaces

AI・エージェントインターフェースへの応用

Classic interfaces

The system image is physical — buttons, icons, menus — and fairly stable across sessions

Agent interfaces

The "system image" is mostly words and behavior — what the agent says it can do, and whether it keeps that promise

A cognitive walkthrough works on an agent too — the "actions" are just conversational turns instead of clicks.

Today's Activity: Cognitive Walkthrough

今日のアクティビティ：認知的ウォークスルー

What You'll Do | やること

  1. Pick a short task (3–5 steps) in an interface — reuse your Week 2 audit interface if you like, or choose an AI assistant task
  2. With a partner, run the four questions at every step
  3. Write a failure story for every "no" or "maybe"
  4. Propose one fix for your most serious failure story
  5. Write up your own walkthrough individually
