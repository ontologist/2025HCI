Week 3: Cognitive Walkthrough

Evaluating Learnability Without Recruiting a Single User

第3週：認知的ウォークスルー — ユーザーを一人も集めずに学習しやすさを評価する

📋 Assignment Overview / 課題概要

In this assignment, everyone runs a four-question cognitive walkthrough on the same prescribed task: a fixed, 5-step conversation with an AI assistant of your choice. For each step, you'll answer the four questions from class, write a failure story for any "no" or "maybe," and propose one concrete fix.

この課題では、全員が同じ、あらかじめ決められたタスクに対して、4つの質問による認知的ウォークスルーを行います。それは、選んだAIアシスタントとの、固定された5ステップの会話です。各ステップについて、授業で学んだ4つの質問に答え、「いいえ」または「おそらく」に対してフェイラーストーリーを書き、具体的な修正案をひとつ提案します。

🎯 Learning Objectives / 学習目標

  • Apply the four cognitive walkthrough questions (Wharton et al., 1994) at each step of a fixed task
  • Turn a "no" or "maybe" answer into a specific, written failure story
  • Connect a failure story to a concrete redesign fix
  • Notice how the same task can behave differently across different AI assistants
  • Practice the course's AI transparency habit

固定されたタスクの各ステップに、4つの認知的ウォークスルーの質問（ウォートンほか、1994年）を適用する。「いいえ」または「おそらく」という答えを、具体的で書き起こされたフェイラーストーリーに変える。フェイラーストーリーを具体的な再デザイン案に結びつける。同じタスクでも、AIアシスタントによって挙動が異なることに気づく。授業のAI透明性の習慣を実践する。

📝 Activity Description / アクティビティ説明

Step 1: The Prescribed Task (指定されたタスク)

Everyone in the class does this exact task — only which AI assistant you use is your choice (ChatGPT, Claude, Gemini, Copilot, or similar).

  1. Open a new chat (not an old one)
  2. Send this message, word for word: "Give me 3 specific tips for studying for a human-computer interaction exam. Format them as a numbered list."
  3. Read its reply
  4. Send this message, word for word: "Turn that into a printable checklist, with a checkbox next to each tip."
  5. Read its final reply, and check: did you actually get checkboxes?

クラス全員が、この全く同じタスクを行います。選べるのは、使うAIアシスタント（ChatGPT、Claude、Gemini、Copilotなど）だけです。新しいチャットを開く（古いものではなく）。このメッセージを一字一句そのまま送る。「人間とコンピュータの相互作用（HCI）の試験勉強のための、具体的なヒントを3つください。番号付きリストの形式でお願いします。」返信を読む。このメッセージを一字一句そのまま送る。「それを、印刷できるチェックリストに変えてください。各ヒントの横にチェックボックスをつけてください。」最後の返信を読み、実際にチェックボックスになっているか確認する。

Step 2: Run It and Observe (実行して観察する)

  • Actually do the 5 steps above — don't just imagine how it would go
  • Note which AI assistant you used, and anything that surprised you at any step, especially step 5

上記の5つのステップを実際に行ってください。どうなるか想像するだけではいけません。使用したAIアシスタントと、どのステップでも、特にステップ5で、驚いたことがあれば記録してください。

Step 3: Ask the Four Questions at Every Step (4つの質問)

#Question日本語
1Will the user try to achieve the right effect?ユーザーは正しい効果を達成しようとするか
2Will the user notice that the correct action is available?ユーザーは正しいアクションが利用可能だと気づくか
3Will the user associate the correct action with the effect they want?ユーザーは正しいアクションを、求めている効果と結びつけるか
4If they perform it, will they see that progress is being made?それを行ったとき、進捗があったとわかるか

Answer yes / maybe / no for each question, at each step.

各ステップで、それぞれの質問に「はい」「おそらく」「いいえ」で答えてください。

Step 4: Write Failure Stories (フェイラーストーリー)

  • For every "no" or "maybe," write a short, specific hypothesis of where and why a real user would get stuck
  • Vague answers like "it's confusing" are not failure stories — name the exact question that failed and why

「いいえ」または「おそらく」のすべてについて、実際のユーザーがどこで、なぜつまずくかという、短く具体的な仮説を書いてください。「わかりにくい」のような曖昧な答えはフェイラーストーリーではありません。どの質問が、なぜ失敗したかを具体的に挙げてください。

Step 5: Propose One Fix (修正案)

  • Pick your most serious failure story
  • Describe one concrete change that would fix it

最も深刻なフェイラーストーリーを選んでください。それを直す具体的な変更を1つ説明してください。

📦 Deliverables / 提出物

Cognitive Walkthrough Report

Format: PDF document (2–3 pages) or slides

Required Components:
  • AI assistant used: which one, and why you picked it
  • The 5 fixed steps: listed, with what actually happened at each one (especially step 5)
  • Four-question table: your yes/maybe/no answer for each of the 5 steps and 4 questions
  • Failure stories: one per "no" or "maybe" answer
  • Redesign fix: one concrete change for your most serious failure story
  • AI transparency log (if used): tool, date, what you asked, what you kept or changed, how you checked it

使用したAIアシスタント（どれを選んだか、なぜか）。5つの固定ステップ（各ステップで実際に何が起きたか、特にステップ5）をリストにする。4つの質問の表（5つのステップと4つの質問それぞれへの、はい／おそらく／いいえの答え）。フェイラーストーリー（「いいえ」または「おそらく」ごとに1つ）。再デザイン案（最も深刻なフェイラーストーリーに対する具体的な変更1つ）。AI透明性ログ（使用した場合）：ツール、日付、尋ねた内容、残した・変更した内容、確認方法。

✅ Submission Requirements / 提出要件

  • File Format: PDF (preferred)
  • File Naming: LastName_FirstName_Week03.pdf
  • Length: 2–3 pages
  • Work style: you may run the walkthrough with a partner in class, but write and submit your own report individually
  • Due Date: Before next class session

ファイル形式：PDF（推奨）。ファイル名：LastName_FirstName_Week03.pdf。長さ：2〜3ページ。進め方：授業中はパートナーと一緒にウォークスルーを行っても構いませんが、レポートの記述と提出は個人で行ってください。締め切り：次の授業までに。

🤖 AI Use on This Assignment / この課題でのAI使用

Since the task itself is a conversation with an AI assistant, you're evaluating one AI assistant as the subject of this assignment. A second AI assistant can still help you draft failure stories or sanity-check your four-question answers — just keep the two uses clearly separate in your write-up.

タスク自体がAIアシスタントとの会話なので、この課題では1つのAIアシスタントを評価対象としています。別のAIアシスタントを、フェイラーストーリーの下書きや、4つの質問への答えの確認に使うこともできます。ただし、その2つの使い方は、記述の中で明確に区別してください。

If you use one, log it: which tool, when, what you asked, what you kept or changed, and how you checked it.

使った場合は記録してください。どのツールを、いつ、何を尋ねて、何を残し・変更し、どう確認したか。

💡 Tips for Success / 成功のためのヒント

  • Type the exact wording: the two messages are given word for word on purpose — paraphrasing them changes the task, which breaks the comparison across the class
  • Pretend you've never seen the worked example: a cognitive walkthrough only works if you're honestly hard on the design, not generous because you already know what to expect
  • A "no" is a good result: finding a real failure story is the point of the assignment, not a sign you did something wrong
  • Drive your own device if you can: even in a pair, watching is not the same as seeing the system image yourself — swap who's typing partway through if you share one device

正確な文言を入力してください。2つのメッセージは、意図的に一字一句指定されています。言い換えると、タスクが変わってしまい、クラス全体での比較が崩れます。ワークド・エグザンプルを見たことがないふりをしてください。認知的ウォークスルーは、すでに何が起こるか知っているからと甘く評価するのではなく、正直に厳しくあたる場合にのみ機能します。「いいえ」は良い結果です。本物のフェイラーストーリーを見つけることがこの課題の目的であり、何か間違えた印ではありません。できれば、自分の端末で操作してください。ペアであっても、見ているだけでは、自分でシステムイメージを見ることと同じではありません。1つの端末を共有する場合は、途中でタイプする人を交代してください。
