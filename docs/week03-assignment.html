Week 3: Cognitive Walkthrough

Evaluating Learnability Without Recruiting a Single User

第3週：認知的ウォークスルー — ユーザーを一人も集めずに学習しやすさを評価する

📋 Assignment Overview / 課題概要

In this assignment, you'll run a four-question cognitive walkthrough on a short task in a real interface — including, optionally, a task you give an AI assistant. For each step, you'll answer the four questions from class, write a failure story for any "no" or "maybe," and propose one concrete fix.

この課題では、実際のインターフェースにおける短いタスクに対して、4つの質問による認知的ウォークスルーを行います。AIアシスタントに与えるタスクを選んでも構いません。各ステップについて、授業で学んだ4つの質問に答え、「いいえ」または「おそらく」に対してフェイラーストーリーを書き、具体的な修正案をひとつ提案します。

🎯 Learning Objectives / 学習目標

  • Break a task down into discrete, evaluable steps
  • Apply the four cognitive walkthrough questions (Wharton et al., 1994) at each step
  • Turn a "no" or "maybe" answer into a specific, written failure story
  • Connect a failure story to a concrete redesign fix
  • Practice the course's AI transparency habit if you use an AI assistant for any part of this work

📝 Activity Description / アクティビティ説明

Step 1: Choose a Task (タスク選択)

  • Pick one short task, 3–5 steps, in an interface you use
  • You may reuse your Week 2 Human Factors Audit interface, or pick a new one
  • Consider choosing a task you give an AI assistant (e.g. "ask it to summarize a file" or "ask it to book something") — agent tasks are especially interesting to walk through

Step 2: List the Steps (ステップのリスト化)

  • Write out each discrete action the user takes, in order
  • Keep steps small enough that each one can be judged on its own

Step 3: Ask the Four Questions at Every Step (4つの質問)

#Question
1Will the user try to achieve the right effect?
2Will the user notice that the correct action is available?
3Will the user associate the correct action with the effect they want?
4If they perform it, will they see that progress is being made?

Answer yes / maybe / no for each question, at each step.

Step 4: Write Failure Stories (フェイラーストーリー)

  • For every "no" or "maybe," write a short, specific hypothesis of where and why a real user would get stuck
  • Vague answers like "it's confusing" are not failure stories — name the exact question that failed and why

Step 5: Propose One Fix (修正案)

  • Pick your most serious failure story
  • Describe one concrete change that would fix it

📦 Deliverables / 提出物

Cognitive Walkthrough Report

Format: PDF document (2–3 pages) or slides

Required Components:
  • Task and interface: what you tested, and why
  • Step list: every action in the task, in order
  • Four-question table: your yes/maybe/no answer for each step and question
  • Failure stories: one per "no" or "maybe" answer
  • Redesign fix: one concrete change for your most serious failure story
  • AI transparency log (if used): tool, date, what you asked, what you kept or changed, how you checked it

✅ Submission Requirements / 提出要件

  • File Format: PDF (preferred)
  • File Naming: LastName_FirstName_Week03.pdf
  • Length: 2–3 pages
  • Work style: you may run the walkthrough with a partner in class, but write and submit your own report individually
  • Due Date: Before next class session

🤖 AI Use on This Assignment / この課題でのAI使用

An AI assistant can help you draft failure stories or sanity-check your four-question answers — and if you picked an AI assistant as your task, you're evaluating one while possibly using another.

If you use one, log it: which tool, when, what you asked, what you kept or changed, and how you checked it.

💡 Tips for Success / 成功のためのヒント

  • Pretend you've never used it: a cognitive walkthrough only works if you're honestly hard on the design
  • Small steps, not big ones: "complete checkout" is too big; "tap the Buy button" is the right size
  • A "no" is a good result: finding a real failure story is the point of the assignment, not a sign you did something wrong
  • If you evaluated an AI agent: treat each conversational turn as one step
